# プロジェクトの開発ルール

この記載例は自動適用の方針を残したい場合に使う。必要な部分を対象プロジェクトの既存ルールへ統合し、手順は Skill に任せる。

## Skill の適用

- 仕様策定、機能追加・振る舞いの変更には HQv2 の `sdd` を使う。仕様を変えない軽微な修正では、新しい仕様文書を省略できる。
- セッションを跨ぐ相談・作業の記録と再開には HQv2 の `steering` を使う。短時間で完了し、引き継ぐ内容のない修正に記録を一律に要求しない。
- 両 Skill は単独でも使える。利用できない場合は報告し、既存規約とユーザーの指示から進め方を決める。

## 文書の配置

- SOT は `docs/PRD.md`、`docs/FDS.md`、`docs/ADD.md`。既存の同等文書があればそれを使う。
- REPO・DEV・GLOSSARY は必要に応じて独立させる。
- 作業記録は `.hq/v2/steering/`。要求・設計・タスクは分割を標準とし、短い内容は節を分けて統合してよい。

## プロジェクト固有の規約

作業ブランチ、PR、起動・検証コマンドなどをここ、または参照する開発文書に記載する。
既存の設定・規約を優先し、実在しないコマンドを作らない。未実施の検証を成功扱いしない。
