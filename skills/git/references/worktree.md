# worktree の標準運用と上書き

利用先の `AGENTS.md` またはそこから参照する規約で指定された項目を優先し、未指定の項目には以下の標準運用を適用する。新規作業では、確定したベースブランチ上の規約も確認する。明示的な依頼は規約と標準運用に優先する。

以下の節はそのまま利用先の `AGENTS.md` へ転記し、変更したい項目を編集できる。全項目の転記や設定ファイルの新設は不要。

## worktree 運用

- 新規作業: ファイル変更を始める前に、確定したベースブランチから作業ブランチと専用 worktree を作成する。相談・参照だけの場合は作成しない。
- 再開: 対応する作業ブランチと worktree を再利用する。セッション開始時に今回の作業専用として用意済みの worktree も使い、重ねて作成しない。
- 配置: 基準 checkout の `.hq/v2/.ignore/worktrees/<作業名>/` とする。基準 checkout は指定がなければ Git の主作業ツリーとし、作成した worktree 内には入れ子で作成しない。作業名は英小文字・数字・ハイフンとし、既存パスと重なる場合は接尾辞で区別する。
- 長期開発系列: 別系列が必要な場合に、系列ごとのベースブランチと保持する worktree を指定する。個別作業は対象系列のベースから分岐する。
- 環境準備: 作成先でプロジェクト指定のコピー・セットアップ手順を実行する。
- 完了後: 取り込み済みで未コミット変更がなく、利用が終わった個別作業用の worktree を削除する。長期開発系列用の worktree は保持する。

## 長期開発系列と個別作業

長期開発系列の維持と、ベースブランチに取り込む個別作業の分離は併用できる。例えば `develop-next` を長期系列として保持し、そのベースから個別作業用のブランチと worktree を作成する。長期系列を設けないプロジェクトでは、通常のベースブランチから個別作業を始める。

長期系列の既存 worktree で作業ブランチを切り替えて使う運用も、利用先で指定できる。worktree の保持期間と作業ブランチの寿命は別に定め、ブランチを切り替えても作業ごとの取り込み先を保持する。

## 上書き例

作成方針だけを変更する場合は、利用先の `AGENTS.md` に次のいずれかを記載する。他の項目には標準運用を適用する。

- 都度判断: 「新規作業では、並行作業や既存 checkout への影響を踏まえて、専用 worktree の作成か既存 checkout の利用かを判断する。」
- 既存環境を使う: 「新規作業では、既存 checkout で作業ブランチを切り替える。専用 worktree は依頼された場合に作成する。」

配置だけを変える場合は、例えば「worktree の作成先は、基準 checkout と同じ親ディレクトリの `<リポジトリ名>-worktrees/<作業名>/` とする。」と指定する。CLI やアプリの管理先を使いたい場合も、その旨を指定する。

## 作成・再利用・整理の確認

対象と基準 checkout は `git worktree list --porcelain` などの Git の情報で確認する。既存変更と他セッションの作業を保全し、作成先が Git 管理対象外であることを確認する。標準配置では `/.hq/v2/.ignore/` を基準 checkout の `.gitignore` 等で除外し、作成先のローカル設定も除外する。

配置を指定できる作成方法を使う。指定配置を扱えないツールでは、Git CLI など指定に対応する方法を選ぶ。作成先で作業を続け、対象ブランチの取り込み先は [設定と保存先](settings.md) に従って記録する。

開発用設定は利用先が指定した対象だけをコピーし、既存設定の上書きや秘密情報の出力を避ける。接続先や保存先の共有で並行作業が干渉する場合は分離する。製品ごとのコピー・セットアップ方法は [README](../../../README.md#worktree-に開発用のローカル設定を用意する) を参照する。

整理前には、未追跡・Git 除外ファイルを含む必要なローカルデータと、他セッションや Plugin 登録元としての利用が終わったことを確認する。作業中・未取り込み・保留中の worktree は保持し、削除に強制オプションを使わない。ブランチの削除は別に判断する。
