# 完了した作業記録を整理する

作業記録の状態を確認し、完了した記録を安全に削除する。状態の食い違いや不足は報告し、判断できないものは残す。wip などの他の Skill の使用履歴を前提にせず、記録の形式だけを使う。Issue のクローズ、ブランチ・worktree の削除、merge は行わない。

判断には、取り込み先の remote（GitHub）と Git の履歴から分かる事実だけを使う。手元の環境に依存しないため、GitHub Actions などのローカル以外の環境でも同じ手順で実行できる。ローカルの worktree の確認や後片付けは、この Skill の範囲に含めない。

記録の形式・状態の変更・削除の条件は [作業記録の形式と整理](../../docs/work-records.md) に従う。この Skill はその規則で点検・整理する手順を担う。

## 開始と範囲

CWD から Git のルートを取得し、利用先の指示、Git 規約、関連する open PR、未コミット変更と進行中の Git 操作を確認する。Gotchas の記録（`.hq/v2/settings.json` の `gotchas.path`、未指定は `GOTCHAS.md`）や同等の記録があれば、今回に関連する項目を参照する。

作業記録の保存先は `.hq/v2/settings.json` の `wip.path`、未指定なら `wip`。以下の `wip/` は設定した保存先を指す。

取り込み先のブランチは、利用先の規約・設定（作業ブランチの記録、`git.baseBranch` など）や依頼から確定し、remote を fetch して最新の状態を基準にする。`main` などを推測で決めない。確定できなければ確認する。

依頼の範囲で実行する。読み取りだけの依頼では変更しない。定期実行の依頼は、その指示が許す範囲（編集・コミット・push・PR）に限る。fetch・API・認証の失敗を「変更なし」と扱わず、確認できない根拠に依存する整理は保留する。

## 判定する

Plugin ルートの `scripts/wip.py` で状態を確認する。`<HQ_ROOT>` は Plugin のルート（ローカル以外の環境では HQ の checkout）、`<対象>` は利用先のルート、`<取り込み先>` は fetch 済みの remote のブランチ（例: `origin/develop`）に置き換える。

```bash
python3 "<HQ_ROOT>/scripts/wip.py" list --repo "<対象>"
python3 "<HQ_ROOT>/scripts/wip.py" sweepable --repo "<対象>" --base "<取り込み先>"
```

| 判定 | 意味 | 扱い |
| --- | --- | --- |
| `deletable` | 削除の条件を満たす | 削除の前の確認へ進む |
| `waiting` | `done` だが、取り込み先にはまだ `done` として入っていない | 残す。取り込み後に再判定する |
| `changed` | 取り込み先と内容が異なる、または Git の管理外のファイルがある | 残す。差分や管理外のファイルの扱いを確認する |
| `not-done` | `active` または `paused` | 残す。下記の観点で点検する |
| `invalid` | `status.json` がない、または不正 | 削除しない。状態の追加・修正を提案する |

スクリプトを使えない場合も同じ条件で判断し、`deletable` に当たらない記録を削除しない。

## 点検の観点

記録ごとに `status.json`、要求の4項目（Goal・Context・Constraints・Done When）、設計・タスクの現在地を読み、次を照合する。

- **状態と根拠**: `prs` の PR の base・merge の有無、Issue の状態、取り込み先に入った変更を記録と比べる。close と merge を区別する。PR の取り込みや Issue のクローズは Done When を確かめる材料であり、それだけでは完了としない。
- **終了条件と残作業**: Done When、未決事項、未反映事項、検証結果を読み、各条件の充足を根拠で確認する。実機確認待ちを実施済みに書き換えない。Done When がない記録は、完了を判断できないものとして扱う。
- **継続・保留・取りやめ**: 再開の見込み、明示された保留・取りやめを確認する。更新が古いだけで取りやめや長期保留を推測しない。引き継ぎ先・残件の所有先を確認する。
- **継続して必要な知識**: 現行の仕様・運用・制約・判断のうち、記録だけにある内容を特定する。既存の正式な文書と照合し、合意と根拠がある内容だけを関連文書へ反映する。新しい仕様・方針は判断せず、確認事項として残す。
- **他の作業との競合**: remote で、記録を変更している open PR と、取り込み先に入っていないブランチを確認する。更新中・使用状況が不明な記録は今回の対象から外す。ローカルの worktree や未コミット変更は確認の前提にしない。他の作業を終了扱いにしたり、残件を肩代わりしたりしない。

## 変更する

- **削除**: `deletable` の記録のうち、継続して必要な知識の反映が済んだものを削除する。記録への参照は、反映先か、取り込み先のコミットを固定した URL に付け替え、削除と同じコミットに含める。
- **状態の更新**: [状態の変更](../../docs/work-records.md#状態の変更) の条件を根拠で確認できた場合だけ、`status.json` と概要の状態を更新する。Done When の充足を確認できた完了と、明示された取りやめは `done` にできる。`done` にした変更では記録を削除しない。PR の取り込みなど確認できた事実は、状態を変えずに現在地へ反映できる。
- **報告だけ**: 条件を確認できない状態の変更（例: PR はすべて取り込まれたが Done When の充足を確認できない `active`）、Done When のない記録、`invalid`・`changed`・`waiting`、競合で外した記録。状態を変える場合に必要な確認事項を添える。

確認日だけの更新、文章の好みだけの整形、全記録への定型文の追加はしない。未採用案や過去の判断を、現在の合意や実装済みの事実へ書き換えない。

変更を作業記録・知識の反映先・参照の修正に限り、整理のために製品コードや配布設定を変更しない。利用先の必須検証を実行し、失敗したらコミット・push を止める。

## PR にする

コミット・push・PR は依頼の範囲で行う。sweep の PR は次の固定の形にし、繰り返し実行しても同時に開く PR を一つに保つ。利用先の規約で別の指定があれば従う。

- ブランチは `chore/sweep`、タイトルは `chore: sweep work records`、ラベルは `hq:sweep`。
- ラベル `hq:sweep` がリポジトリになければ作成する。
- 開いている sweep の PR（ラベル `hq:sweep` またはブランチ `chore/sweep`）があれば、新しく作らずに更新する。作成直前と push 前にも、取り込み先と既存の PR の状態を確認し直す。
- 取り込み済みの sweep の PR のブランチは使わず、最新の取り込み先から作る。同名のブランチが残っていて使えない場合は、強制的に上書きせず、接尾辞で区別する。
- 人が閉じた未取り込みの sweep の PR は、理由を確認するまで作り直さない。
- 本文には、記録ごとの判定・根拠、削除した記録の最終内容を含む取り込み先のコミットへのリンク、検証結果、報告だけの事項を示す。

## 結果を伝える

記録ごとの判定・扱い・根拠、削除した記録と参照の付け替え先、更新した状態、報告だけの事項、見送った理由を伝える。変更も新しい確認事項もなければ、その旨を簡潔に伝える。実行できなかった点検を成功として扱わない。削除した記録を後で参照する方法は [削除した記録の参照](../../docs/work-records.md#削除した記録の参照) を案内する。
