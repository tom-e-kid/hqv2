# 完了した作業記録を整理する

作業記録の状態を確認し、完了した記録を安全に削除する。状態の食い違いや不足は報告し、判断できないものは残す。wip などの他の Skill の使用履歴を前提にせず、記録の形式だけを使う。Issue のクローズ、ブランチ・worktree の削除、merge は行わない。

## 開始と範囲

CWD から Git のルートを取得し、利用先の指示、Git 規約、関連する open PR、未コミット変更と進行中の Git 操作を確認する。Gotchas の記録（`.hq/v2/settings.json` の `gotchas.path`、未指定は `GOTCHAS.md`）や同等の記録があれば、今回に関連する項目を参照する。

作業記録の保存先は `.hq/v2/settings.json` の `wip.path`、未指定なら `wip`。以下の `wip/` は設定した保存先を指す。記録は `wip/<作業名>/` のディレクトリで、`status.json` に状態（`active`・`paused`・`done`）・重み・PR 番号を持つ。

取り込み先のブランチは、利用先の規約・設定（作業ブランチの記録、`git.baseBranch` など）や依頼から確定し、remote を fetch して最新の状態を基準にする。`main` などを推測で決めない。確定できなければ確認する。

依頼の範囲で実行する。読み取りだけの依頼では変更しない。定期実行の依頼は、その指示が許す範囲（編集・コミット・push・PR）に限る。fetch・API・認証の失敗を「変更なし」と扱わず、確認できない根拠に依存する整理は保留する。

## 判定する

Plugin ルートの `scripts/wip.py` で状態を確認する。`<HQ_ROOT>` は Plugin のルート、`<対象>` は利用先のルート、`<取り込み先>` は fetch 済みの remote のブランチ（例: `origin/develop`）に置き換える。

```bash
python3 "<HQ_ROOT>/scripts/wip.py" list --repo "<対象>"
python3 "<HQ_ROOT>/scripts/wip.py" sweepable --repo "<対象>" --base "<取り込み先>"
```

| 判定 | 意味 | 扱い |
| --- | --- | --- |
| `deletable` | `done` の記録が、作業ツリーと同じ内容で取り込み先にある | 削除の前の確認へ進む |
| `waiting` | `done` だが、取り込み先にはまだ `done` として入っていない | 残す。取り込み後に再判定する |
| `changed` | 取り込み先の記録と作業ツリーの内容が異なる | 残す。差分の扱いを確認する |
| `not-done` | `active` または `paused` | 残す。下記の観点で点検する |
| `invalid` | `status.json` がない、または不正 | 削除しない。状態の追加・修正を提案する |

スクリプトを使えない場合も同じ基準で判断する。`deletable` 以外を削除しない。取り込み方法（マージコミット・squash・rebase）は利用先の運用に任せ、判定は取り込み先の内容だけで行う。

## 点検の観点

記録ごとに `status.json`、要求（`requirements.md` または `work.md` の Goal・Context・Constraints・Done When）、設計・タスクの現在地を読み、次を照合する。

- **状態と根拠**: `prs` の PR の base・merge の有無、Issue の状態、取り込み先に入った変更を記録と比べる。PR が複数ある作業では一件の merge だけで完了としない。close と merge を区別し、Issue が閉じているだけで Done When の充足としない。
- **終了条件と残作業**: Done When、未決事項、未反映事項、検証結果を読む。マージやチェックボックス、経過日数だけでは完了にしない。実機確認待ちを実施済みに書き換えず、作業全体の残件かを記録に基づいて区別する。Done When がない記録は、完了を判断できないものとして報告する。
- **継続・保留・取りやめ**: 再開の見込み、明示された保留・取りやめを確認する。更新が古いだけで取りやめや長期保留を推測しない。引き継ぎ先・残件の所有先を確認する。
- **継続して必要な知識**: 現行の仕様・運用・制約・判断のうち、記録だけにある内容を特定する。既存の正式な文書と照合し、合意と根拠がある内容だけを関連文書へ反映する。新しい仕様・方針は判断せず、確認事項として残す。
- **他の作業との競合**: 関連するブランチ・worktree・open PR に進行中の更新がないか確認する。活動中・未コミット変更あり・使用状況が不明な記録は今回の対象から外す。他の作業を終了扱いにしたり、残件を肩代わりしたりしない。

## 変更する

- **削除**: `deletable` の記録のうち、継続して必要な知識の反映が済んでいるものを削除する。記録への参照は、反映先か、取り込み先のコミットを固定した URL に付け替え、付け替えずに取り除かない。削除と参照の整理は同じコミットに含める。最終記録は既に取り込み先にあるため、どの取り込み方法でも履歴から参照できる。
- **状態の更新**: 根拠で確かめた事実（PR の取り込みなど）に限り、`status.json` と概要の状態を更新できる。`done` への変更は Done When の充足を確認できた場合だけとし、その変更では記録を削除しない。判断できなければ提案に留める。
- **報告だけ**: `invalid`・`changed`・`waiting`、PR がすべて取り込まれたのに `active` の記録、Done When のない記録、競合で外した記録。

確認日だけの更新、文章の好みだけの整形、全記録への定型文の追加はしない。未採用案や過去の判断を、現在の合意や実装済みの事実へ書き換えない。

ブランチ・コミット・PR は利用先の規約と依頼の範囲で行う。変更を作業記録・知識の反映先・参照の修正に限り、整理のために製品コードや配布設定を変更しない。利用先の必須検証を実行し、失敗したらコミット・push を止める。

## 結果を伝える

記録ごとの判定・扱い・根拠、削除した記録と参照の付け替え先、更新した状態、報告だけの事項、見送った理由を伝える。変更も新しい確認事項もなければ、その旨を簡潔に伝える。実行できなかった点検を成功として扱わない。

削除した記録を後で参照するときは、マージをまたいだ記録が通常の `git log -- <パス>` に表示されないことがあるため、`git log --full-history -- <パス>` で探し、削除コミットの親から取り出す。
