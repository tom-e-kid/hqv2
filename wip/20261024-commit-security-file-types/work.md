概要: [Issue #27](https://github.com/tom-e-kid/hqv2/issues/27) に対応する。コードの変数名・型名による `secret-assignment` の誤検出を拡張子ごとの値の読み方で減らし、既知の画像・文書・フォントで `unscannable` を出すかを利用先が選べるようにする。例外の管理（[Issue #28](https://github.com/tom-e-kid/hqv2/issues/28)）は別の作業とする。

## Goal

- 引用符で文字列を書く言語のファイルで、引用符なしの値（変数・引数・型の参照）を `secret-assignment` の具体値とみなさない。二重引用符の値に、その言語が実際に補間する書き方を含む場合は式とみなす。
- 既知の画像・文書・フォントのバイナリで `unscannable` を出すかを、利用先が `.hq/v2/security.json` で切り替えられるようにする。既定は従来どおり止める。
- 拡張子の対応と、バイナリの対象の拡張子は、HQ の既定を利用先が追加・変更できる。
- 対象外: 設定形式（YAML・INI・properties・TOML・シェル・`.env`）と不明な拡張子の判定の変更、検出範囲の拡大（型を注釈した宣言、接頭辞付きの文字列、バッククォートの文字列、Go の `:=`、区切りのない camelCase のキー）、#28 の内容。検出しない書き方は参照文書に明記する。

## Constraints

- 拡張子で検査自体を省かない。コメントの中も検査する。既知の形式のトークン・秘密鍵・ローカルパスは補間の有無を問わず検出する。
- 不明な拡張子は従来の判定（安全側）にする。不正な設定は既定値に戻さず、チェックを止める（R1）。
- 設定はステージした `.hq/v2/security.json` から読み、例外と同じくコミットでレビューできるようにする。
- 例外の考え方（レビューした内容だけを通す）は変えない。

## 設計と判断理由

- 値の読み方を拡張子ごとに `config`・`quoted`・`swift`・`kotlin`・`ruby` のいずれかにする。`config` は従来の判定、他は引用符付きの値だけを具体値とし、補間の書き方が異なる。名前は代表的な言語で、`kotlin` は Dart・Groovy・PHP にも使う。構文名（`dollar` 等）より読みやすさを優先した。JavaScript・TypeScript は、補間するバッククォートの文字列を値として読まないため `quoted` とする。
- 補間とみなすのは、二重引用符の値で、直前のバックスラッシュが偶数個（エスケープされていない）の、その言語の書き方だけとする。単引用符の値は補間とみなさない。Dart は単引用符でも補間するが、具体値として検出する（止める側）。
- 補間を一つでも含む値は、値全体を式とみなす。補間を除いた残りで判定する案は、`"Authorization: Bearer \(token)"` のような行を誤検出するため採らなかった。見逃しは、言語が実際に補間する値に、形式の分からない秘密値をつなげて書いた場合に限られ、既知の形式は `service-token` が検出する。
- 拡張子はファイル名の末尾と大文字・小文字を区別せず照合し、長いほうを優先する。拡張子のないファイル（`Fastfile` 等）は指定の対象外で `config` のまま。
- バイナリを止めない設定でも、10 MiB 超のファイルは中身を検査しないため止める。`.docx` 等の圧縮形式は読める部分の検査がほとんど働かないため既定の対象に含めない。
- 設定はポリシーの省略可能な `rules` に置き、version 1 のままにする。既存のポリシーはそのまま使える。以前のコピーは `rules` を不正として止める（安全側）。`status` の `update-available` で更新の必要が分かる。version の扱いは fingerprint の計算を変える #28 で決める。

## PR レビューの指摘への対応

2026-10-24 に利用者が共有したレビューの指摘を確認し、すべて再現した。

- 補間の判定が引用符の種類とエスケープを見ていなかった（要修正）。PHP・Groovy・Ruby・JS の単引用符、Kotlin・PHP の `\$`、JS/TS の引用符内の `${…}` を補間とみなし、変更前は検出していた値を見逃していた。再現テストを追加して修正前に10件の失敗を確認し、上記の設計に修正した。JS/TS の `${…}` を正しい補間として固定していたテストも改めた。
- 型を注釈した宣言（`let apiKey: String = "…"` 等）を検出しない（判断が必要）。型名が8文字未満なら変更前から検出せず、長い型名は変更前には型名の誤検出で止まっていたが、この変更で通る。レビューの推奨どおり、この PR では検出しない書き方として参照文書に明記し、検出への対応は別の Issue とする。作業記録の対象外（検出範囲の拡大）と合わせるため。
- 設定キーの説明（英小文字）が実装（大文字・小文字を区別しない）と食い違っていた（軽微）。参照文書を実装に合わせた。
- 範囲外: `dbPassword` のように区切りのない camelCase のキーを検出しない（変更前から）。参照文書の検出しない書き方に明記し、別の Issue とする。
