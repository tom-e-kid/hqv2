# 作業記録を最後の PR で完了にする規則の要求

状態: 合意した方針を実装・検証中。具体的な対象取得・再実行の方式は設計に記載する。

## Goal

作業記録の `done` を、作業の最後の PR の中で取り込み前に設定する。Done When は取り込みまでに確認できる条件に限り、取り込み後にしか確認できない事項は検証資料・チェックリストで別に管理する。

PR 作成前の Pre チェックで確認が必要な作成呼び出しを一旦止め、エージェントが最後の PR かを判断・対応した後に再実行できるようにする。中間 PR の `active` を機械で不正とせず、状態を自動変更しない。

対象: 共通規則、wip・pr・git・sweep の手順、要求の雛形、Codex・Claude Code の Plugin Hook、検証資料、CHANGELOG。記録の削除条件・既存の作成後 SSOT 確認・AI レビュー監視の責務は変えない。

## Context

取り込み後に完了状態を付ける運用では、それだけの追加変更が必要になる。取り込み後の運用確認を Done When に含めると、最終記録が完了状態で取り込まれないまま残る。最後の PR に最終記録を含め、削除は後の別変更とする。

規則は [作業記録の形式と整理](../../docs/references/work-records.md)。SSOT は `docs/ssot/` に登録されており、PRD 全体は草案。合意済みの文書配置と今回の方針を反映し、草案全体の合意とは区別する。Gotchas の「再現性を求めて意思決定まで機械判定に置き換えてしまう」を適用し、最後の PR や完了条件の意味はエージェントが判断する。

## Constraints

- 各 Skill は単独で使え、Plugin Hook に依存しない。PR 作成前の停止は利用先が wip.prPreflight: true を明示したリポジトリだけに適用し、未設定・false・Git 外では停止しない。
- 対象不明・取得失敗・状態不正を問題なしと扱わない。対象はホスト・リポジトリ・コミットで固定し、ローカルの現在ブランチから推測しない。
- 状態を自動変更しない。`done` を通過条件として強制せず、中間 PR は理由を記録して再実行できる。
- 必須検証・レビューの未実施を、取り込み自体で満たされる条件の例外として扱わない。
- 取り込み方法を制限しない。完了にした変更で記録を削除せず、取り込み先の最終状態に基づく既存の削除条件を維持する。
- Plugin のインストール・利用先での動作確認・push・PR 作成・取り込みは、実装・検証と別の実行段階として扱う。

## Done When

| 条件 | 確認方法 |
| --- | --- |
| 共通規則・Skill・雛形に、最後の PR で取り込み前に done にし、Done When は取り込みまでの条件とする方針が反映されている | 文書・差分の確認 |
| Pre チェックが確認前に停止し、中間 PR は理由を保存して再実行できる。状態を自動変更せず、不正・取得失敗は未確認として停止する | 入出力・Git/API 境界の自動テスト |
| base/head・対象・worktree が異なる場合に古い判断結果を使わない | 自動テスト |
| 構造・参照・変更 Skill の専用検証・自動テスト・両ツールの配布設定確認が成功し、未確認範囲が記録されている | 開発用検証手順 |
| 最後の PR を用意する際、この記録の done と最終検証結果を同じ PR に含める | 状態ファイル・最終差分の確認 |

利用するツール内での停止と理由の配送・再実行は [検証チェックリスト S52](../../docs/ssot/validation-checklist.md#s52-pr-作成前の作業記録確認) へ残す。未実施を成功にしない。
