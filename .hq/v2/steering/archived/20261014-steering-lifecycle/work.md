# 作業記録の探索と格納位置の見直し

着手日: 2026-10-14（Asia/Tokyo）
状態: 完了
概要: steering の標準配置を active/archived に分け、会話と依頼内容から既存の作業を判断できるようにする。

## 要求と合意

記録の蓄積による全件参照と、毎回の作業指定を減らしたい。ブランチ名を作業選択の唯一の根拠にせず、会話・依頼内容・記録から判断する余地を残す。

2026-10-14: ユーザーの「archiveはarchivedの方が好みかな。で、提案の方針で対応してくれる？」を本変更の合意の根拠とする。

同日、作業記録を Git 管理し、本文は現在地、変更の経緯は Git history に残す提案に対する「反映して」を追加変更の合意の根拠とする。

同日、ディレクトリの蓄積を避けるため、完了・取りやめの記録は最終内容を Git に残してから削除し、archived は保留・継続参照に使う提案に対する「その想定で更新してくれる？」を合意の根拠とする。「レビューして問題なかったらコミットしてほしい」によりレビューとコミットも依頼された。

## 設計と反映

- 新規作業は `.hq/v2/steering/active/YYYYMMDD-<作業名>/`、再開を見込む当面の保留や継続参照する記録は `archived/` に置く。セッション終了だけでは移動しない。状態と理由は記録内に残す。
- 会話と依頼内容を中心に、ブランチ情報と記録の概要・状態・現在地から既存作業を判断する。固定の選択順序やプロジェクト共通の current は導入しない。
- 通常は active の作業名・短い概要・状態から候補を絞り、対象の記録を読む。archived は過去の判断の参照や再開に必要な場合に確認する。候補を区別できない場合だけ確認する。
- 再開時は同じ記録を使い、標準配置では active に戻す。移動では上書きを避け、参照リンクを確認・更新する。旧配置や独自の配置は尊重し、一律に移行しない。このリポジトリの既存記録も元の位置を保持する。
- steering 本文、tasks の雛形、README、利用先 AGENTS.md の記載例を更新した。要求・設計の雛形や sdd の参照文書には保存先を固定する記載がなく、変更不要。
- 作業記録も Git 管理する前提を明記した。本文は現在の要求・設計・合意・進捗・次の作業を示し、判断理由・検証結果を保持する。変更前の全文は Git history に任せる。記録更新ごとの個別コミットは必須にせず、プロジェクトの規約・ユーザー指示に従い、関連コミットに必要な記録更新・移動・削除も含める。
- 完了・取りやめ時の整理を steering の「検証と完了」に集約した。必要な内容を関連文書へ反映し、最終の状態・理由・検証結果がコミットされていることを確認してから記録を削除する。削除とリンク整理もコミットする。README は方針と手順への参照、利用先の例は配置と Git 管理の前提に留めた。
