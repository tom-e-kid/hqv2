# SOT 維持の強化と文書の分担

状態: 採用された原則を反映。文書の詳細な分担は依頼に基づくエージェントの整理。

## 設計

sdd の原則と変更開発に、着手時の分類・合意後の反映・合意と実装状態の区別・完了時の整合確認を追加する。詳細な文書管理は document-rules に置き、内容の正本と参照は document-roles にまとめる。

PRD は要求・達成基準、FDS は機能の動作・論理モデル・画面・API の契約、ADD は技術構成・実現方式と判断理由を正本にする。REPO は配置、DEV は開発手順・規約、GLOSSARY は用語の意味・表記。オプショナル文書を新設する条件と、新設しない場合の正本も示す。

利用先の指示ファイルには Skill の適用とは独立した SOT 維持の原則を置く。steering に仕様合意・維持の手順を重複して持たせず、相互の Skill 実行を必須にしない。

## 影響範囲

sdd の入口・参照文書・PRD/FDS/ADD の雛形、利用先の AGENTS.md 記載例、README、参照検証の対象一覧。利用先の CLAUDE.md は AGENTS.md を参照するため、原則の複製は不要。

このリポジトリは Plugin の配布リポジトリであり、利用先アプリ用の6文書をここへ一律に作成しない。

## 検証方針

README の構造・参照・Claude マニフェスト・Codex カタログ検証を実施する。文書変更のみのためモデルを呼ぶ動作テストは実施しない。意味上の整合は変更差分と全関連文書を確認する。
