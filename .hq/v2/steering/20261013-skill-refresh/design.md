# 二つの Skill と三つの記載先

状態: 指示に基づく設計を反映

## 関係

- sdd はプロジェクト全体の目的・主要要求・基本設計・方針・制約を相談し docs/ に残す手法。初期だけでなく大枠の見直しにも使える。
- steering は一つの目的・範囲を持つ作業の具体化、実装・検証、記録・再開の手法。
- docs/ は大枠、作業記録は対象の作業の詳細と判断、実装・テストは詳細な構造・動作を持つ。

Skill の呼び出しには依存を作らない。情報の関係は共有し、steering が docs/ の大枠を参照する。大枠変更は合意して反映するが、実装詳細の逐一転記は求めない。

## 変更範囲

sdd の実装中心の参照文書を方針見直しへ置き換える。steering に作業の相談・実装・検証と大枠変更時の判断を定義する。各テンプレートと文書の役割、利用先の記載例、README、Plugin の表示説明、検証スクリプトを揃える。

以前の「現在の全詳細を docs/ に集約する」方向の強化は、この粒度で置き換える。PRD・FDS・ADD の基本構成、REPO・DEV・GLOSSARY のオプショナル区分、まとめて合意する標準、作業記録の保存先は維持する。

## 検証

構造・参照、Claude マニフェスト、Codex カタログ、差分の検証を実施する。文書の判断は大枠策定、詳細の実装、大枠変更、相談だけの完了、再開のケースに当てはめて確認する。モデルを呼ぶ動作テストは未実施とする。
