# SOT の維持と文書の役割

状態: SOT 維持の提案は採用済み。文書の役割を明確化する変更を依頼済み。

## ユーザー要求

`docs/` は常に更新して維持する SOT・北極星とする。2026-10-12、ユーザーは提示した6点の改善案を「提案を採用して」と指示した。その後、各 SOT 文書の役割を明確にし、提示した CLAUDE.md の粒度で重複が出るか確認したいと依頼した。

採用された内容:

- 基本設計の変更に限らず、記載された仕様への影響を更新する。
- 着手時に既存仕様の実現・修正、仕様の追加・変更、仕様不足の検討を判断する。
- 合意した仕様を実装の基準として反映し、合意済みと実装済みを区別する。
- 必要な SOT 更新を作業全体の完了条件にする。
- 各文書の正本と参照を分け、作業記録の決定を SOT の現在の仕様へ統合する。
- 使用する Skill にかかわらず、プロジェクト全体で SOT を維持する。

## 受け入れ条件

- AC-001: 採用された原則が sdd の入口・参照文書・利用先の記載例に反映されている。
- AC-002: PRD・FDS・ADD・REPO・DEV・GLOSSARY の役割と重複しやすい内容の正本が明記され、雛形と整合する。
- AC-003: sdd と steering の独立性、必須・オプショナルの区分、まとめて合意する標準を維持する。
- AC-004: README に記載した構造・参照・マニフェストの検証が通る。
