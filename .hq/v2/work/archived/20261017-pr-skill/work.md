## 要求と変更

ユーザーは、git・release と同じ作業ブランチに独立した pr Skill を追加するよう依頼した。標準の PR 書式を用意し、利用先の `.hq/v2/pr.md` があればその指示・書式を優先する。

- [pr](../../../../../skills/pr/SKILL.md) はタイトル・本文の整理と作成・更新を扱い、他の Skill の実行を必須にしない。
- [標準本文](../../../../../skills/pr/assets/pr-body.md) は「概要・変更・検証」。独自書式を指定された場合は標準見出しを重ねず、指示だけの場合は既存テンプレートまたは標準書式で未指定部分を補う。
- git・release の PR 作業、AGENTS.md・README・配布説明・利用先の記載例・構造検証・CHANGELOG を整合させた。このリポジトリでは独自の `.hq/v2/pr.md` を新設せず標準書式を使う。

## モデルによる動作確認

skill-creator の独立検証手順に従い、相談履歴を持たない別エージェントへ Skill と3つの隔離 Git リポジトリを渡した。各ケースでコミット済みの差分から日本語のタイトル・本文の下書きを作るよう依頼し、期待する正解は渡していない。ネットワーク・GitHub・コミット・push と本番への書き込みを禁止した。

| ケース | 観測した結果 |
| --- | --- |
| `.hq/v2/pr.md`・既存テンプレートともになし | Conventional Commits のタイトルと、標準の「概要・変更・検証」を使用 |
| `.hq/v2/pr.md` の独自書式と、別の既存テンプレートあり | 指定されたタイトル接頭辞と「背景・確認事項」だけを使用。既存・標準の見出しを追加しなかった |
| `.hq/v2/pr.md` は指示のみ、既存テンプレートあり | タイトル接頭辞と互換性の説明を指示に合わせ、見出しは既存の「Context・Evidence」を使用 |

各ケースで実際の差分とローカル検証コマンドの成功を本文に反映し、下書きの作成だけで終了した。親側でも出力の見出し・タイトル・説明内容・未記入の説明文がないことと、各リポジトリの作業ツリーが clean であることを照合した。

上記ケースで問題は観測されなかった。モデルの動作を全ケースで保証するものではなく、複数テンプレートの曖昧な選択や GitHub API の失敗時は今回の隔離確認の対象外。実リポジトリでも、同じ Skill の標準書式に沿って既存 PR #1 の本文を更新した。
