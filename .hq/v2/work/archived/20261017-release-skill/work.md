# release Skill と develop/main 運用の検証

状態: 実装・検証済み。PR #1 で develop へ取り込み済み。検証の根拠として archived に保持。
整理日: 2026-10-18（Asia/Tokyo）。取り込み済みの作業記録を active から移動。
検証確認日: 2026-10-17（Asia/Tokyo）

## 要求と合意

ユーザーは独立した release Skill の作成と、このリポジトリへの develop/main 運用の導入を依頼した。実装後、PyYAML 不足で実行できなかった専用検証と、モデルによる動作確認の未実施を解消するよう求めた。

通常の作業とリリース準備は作業ブランチから develop へ取り込み、公開対象とバージョンを確定してから main へ取り込む。初回予定は 2.0.0。今回の作業は Skill と運用の導入であり、実際のリリース準備・タグ・公開ではない。

## 専用検証の環境と結果

- Python 3.14 の一時仮想環境を作成し、PyYAML 6.0.3 をインストールした。システムの Python は変更していない。
- skill-creator 付属の `scripts/quick_validate.py` を、同じ仮想環境の Python で各 Skill ディレクトリに対して実行した。
- git・gotchas・release・sdd・steering の全5件が `Skill is valid!`、終了コード0。
- PyYAML はこの開発用検証ツールの依存であり、HQ Plugin の実行時依存ではない。利用者にインストールを要求しない。リポジトリの `scripts/validate.py` も Python 標準ライブラリだけで実行できる。

## モデルによる動作確認

skill-creator の独立検証手順に従い、実装相談の履歴を持たない別エージェントへ release Skill と隔離した4つの Git リポジトリを渡した。期待する正解は渡さず、各ケースを独立したユーザー依頼として実行した。本番リポジトリへの書き込み・ネットワーク・公開操作は禁止し、結果のファイル・ブランチ・タグを親側で照合した。

全ケースで開発ブランチを integration、公開ブランチを stable とし、develop/main 固定の前提を持ち込まないことも確認した。git・steering の実行履歴や作業記録は与えていない。

| ケース | 観測した結果 |
| --- | --- |
| 初回公開予定 2.0.0 の準備 | 規約と依頼に従って 2.0.0 を維持。作業ブランチで日付付き CHANGELOG と空の Unreleased を準備し、必須検証が成功。README の開始バージョンを保持し、コミット・タグ・公開は実行しなかった |
| 公開済み 1.0.0 から、合意した 1.1.0 の準備 | 互換性のある機能追加と合意済みの minor を照合。作業ブランチで VERSION と CHANGELOG のみを更新し、必須検証が成功。過去の記録を保持し、コミット・タグ・公開は実行しなかった |
| 必須検証が失敗する環境での準備 | 必須コマンドは終了コード1。アプリ・検証スクリプト・失敗条件を書き換えず、先の段階へ進まなかった |
| 対象コミットと既存の同名タグが異なる状態からの再開 | 対象とタグの参照先・内容を確認し、タグの作り直しや付け替えを実行しなかった。作業ツリー・ブランチ・既存タグは変更なし |

上記ケースにおける問題は観測されなかったため、Skill 本体の追加修正は行っていない。

## 構造・配布設定と検証の限界

- リポジトリの構造・参照・設定 JSON の検証、差分チェックは成功。
- Claude Code のカタログ・マニフェスト検証は成功。README に記載した既知のルート CLAUDE.md 警告のみ。
- Codex のカタログ読み込みで hq@hq-marketplace / 2.0.0 を確認。PATH alias 作成の権限警告あり。
- リリース検証コードは一時 fixture で、初回準備の正常系と、未整理の Unreleased・不正な日付・履歴のバージョン違い・マニフェスト不一致・リポジトリ外のパスの失敗系を確認済み。
- モデルの結果は4ケースで観測した挙動であり、全ケースの保証ではない。remote へのタグ送信・GitHub Release・実際の配布と公開途中のネットワーク障害は実行していない。
