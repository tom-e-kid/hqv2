# HQ の用語集

HQ の [PRD](PRD.md) と関連資料で使う用語の意味・表記を揃える。

| 用語 | 意味 |
| --- | --- |
| SSOT | Single Source of Truth（正本）。プロジェクトの要求・設計・制約について、合意事項と検討中の事項を残し、開発の判断基準とする文書 |
| SDD | スペック駆動開発。仕様を判断基準に開発を進め、方針の変更を仕様に反映する進め方 |
| PRD | Product Requirements Document（プロダクト要求文書）。目的・提供範囲・要求・制約をまとめる文書 |
| FDS | Functional Design Specification（機能設計書）。機能の振る舞い・関係・責務をまとめる文書 |
| ADD | Architecture Design Document（アーキテクチャ設計書）。技術構成・選定理由・実現方針をまとめる文書 |
| REPO | リポジトリ構成資料。ディレクトリの責務・配置・依存関係の境界をまとめる文書 |
| DEV | 開発ガイド。開発環境・検証方法・開発規約をまとめる文書 |
| GLOSSARY | 用語集。用語の意味と推奨表記をまとめる文書 |
| 作業記録 | 一つの作業の要求・設計・進捗・判断理由・検証結果を残す資料一式。標準では `wip/` に置く |
| 利用先プロジェクト | HQ を使って開発・保守するプロジェクトとそのリポジトリ。文脈が明らかな場合は「利用先」と呼ぶ |
| 利用するツール | HQ を読み込んで動かす Codex・Claude Code |
| Git Hook | Git 操作に伴うイベントをきっかけに、Git が実行する処理 |
| Plugin Hook | セッション開始などのイベントをきっかけに、Codex・Claude Code が Plugin の定義に従って実行する処理 |
| Plugin | Codex・Claude Code に Skill や Hook などの機能をまとめて提供する配布単位。HQ は Plugin として配布する |
| Skill | 特定の目的を持つ作業の判断と手順を、参照資料等とともにまとめたもの |
| Gotchas | 利用先プロジェクトで繰り返し遭遇しうる落とし穴と、その根拠・対処を共有する知識 |
| AI レビュアー | PR の変更を確認し、レビューや指摘を投稿する AI |
| フィードバック | レビューやコメントを通じて届く指摘・意見。資料では FB と略さない |
| コミット前チェック | コミット対象の秘密情報らしい値・ローカルパス等を検査する HQ の機能 |
| セッション | Codex・Claude Code が会話や作業の文脈を保持して動作する一連の利用単位 |
| worktree | 一つの Git リポジトリの履歴を共有しながら、別のブランチや変更を扱える作業ツリー |
| 取り込み先 | 作業の変更を取り込むブランチ。利用先プロジェクトとは区別する |
| 対応回数の上限 | PR フィードバック対応で、指摘をまとめて判断・対応する回数の上限。資料では Cap と呼ばない |
| 利用者 | HQ に作業を依頼し、判断・合意を行う人 |
| 対象ユーザー | 利用先プロジェクトが提供するソフトウェアやサービスを使う人。HQ の利用者とは区別する |
