# 実プロジェクト検証チェックリスト

状態: 叩き台。既存の動作確認ケースを移し、導入・ツール固有機能の確認項目を補った。すべて未実施。チェック欄は今回の検証成功を表さない。

## 目的と使い方

用語は [用語集](GLOSSARY.md) に従う。

[PRD](PRD.md) の要求を、HQ を取り込む利用先プロジェクトで確認する。構造検証や API を差し替えた自動テストでは確認できない、エージェントの判断・引き継ぎ・利用するツールの Hook 動作を対象とする。

- 変更に応じてケースを選び、Codex・Claude Code の各ツールで新しいセッションから実行する。一方の結果を他方へ流用しない。
- 対象機能に必要な利用先の許可・設定を確認する。公開・返信等の外部操作は利用先で許可された検証範囲で行う。
- 以下の各ケースの Codex・Claude Code 欄は、そのツールの合格を確認したときだけチェックする。未実施・失敗・対象外は未チェックのまま、結果記録へ状態と理由を残す。
- 継続して使う項目の正本はこの文書とし、実行ごとの結果は利用先の作業記録などへ保存してよい。成功した過去のチェックを新しい対象の成功として引き継がない。
- 初回公開で必須とするケース・利用するツール・利用先の組み合わせは未決。ケース一覧は公開判定の合意済み条件ではない。

## ツール固有機能と自動処理（R1・R4・R5・R6）

### H01: セッション開始時のコミット前チェック状態通知

- [ ] Codex
- [ ] Claude Code
- 期待結果: 未導入は採用宣言のある利用先で通知する。導入後の欠損・変更・更新候補・外部管理経路の未確認を区別し、Hook を自動導入しない。検出対象のコミットを実際に止められ、対象外の操作を保護済みと説明しない。

### H02: PR フィードバックの登録・待機・対応・収束

- [ ] Codex
- [ ] Claude Code
- 期待結果: 許可・有効化した利用先で対象 PR を正しく登録し、Stop による待機・継続、指摘の分類・必要な修正と検証・返信・Resolve・再確認を行える。false のレビュアーも初回は待ち、true の相手は現在の head のレビューを待つ。追加指摘と静穏期間を考慮し、上限・期限・未解決を正しく報告する。

### H03: PR フィードバックの中断と再開

- [ ] Codex
- [ ] Claude Code
- 期待結果: 手動停止、Codex・Claude Code の SessionEnd、Codex の Interrupt、Hook 打ち切り後の次回検出で、停止・取り残し・未処理を区別できる。再開時に処理履歴と上限を保持し、待機や通知を重複させない。

### H04: macOS の待機とスリープ

- [ ] Codex
- [ ] Claude Code
- 期待結果: macOS の利用するツールで、待機中のアイドルスリープ抑止と解除、抑止失敗の通知、手動スリープ後の復帰を確認できる。他の OS は対象外として理由を記録する。プロセスや時刻を差し替えたテストだけで合格にしない。
